# Security Policy
## Supported versions
The latest minor release is supported for security fixes during the pre-1.0 phase.
## Reporting
Do not open public issues for vulnerabilities or leaked credentials. Use GitHub Private Vulnerability Reporting after the repository is published. Until it is enabled, contact the repository maintainers through a private channel listed on the GitHub organization profile.
Include affected version, component, impact, reproduction steps and suggested remediation if known. Do not include real cloud credentials or customer data.
## Response target
We aim to acknowledge a credible report within 3 business days, provide an initial severity assessment within 7 business days, and coordinate remediation/disclosure according to risk.
